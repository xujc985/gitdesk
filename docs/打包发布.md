# GitDesk 多平台打包流程

## 目标产物

| 平台 | 构建脚本 | 产物 | 说明 |
|------|----------|------|------|
| Windows | `packaging/build-windows.ps1` | **`release/*-setup.exe`**、便携 ZIP | **Inno Setup 原生安装程序**，支持安装路径、开始菜单/桌面图标与卸载 |
| Linux | `packaging/build-linux.sh` | **AppImage**、AppDir、tar.gz | 可执行单文件 AppImage，双击运行 |
| macOS | `packaging/build-macos.sh` | **GitDesk.app**、DMG | 标准 .app 应用；DMG 是安装分发容器，不是压缩源码包 |

**不支持从 Windows 交叉打包 Linux/macOS 应用。** 请在对应操作系统构建，或使用提供的 GitHub Actions 三平台矩阵。

## 打包原理

- 使用 PyInstaller **onedir**，包含 Python、Qt Widgets、项目模块和 SVG/PNG/ICO 图标。
- 使用 PySide6 Essentials，不打包 QtWebEngine、QML/Quick、浏览器内核或 Node.js。
- 资源路径自动适配源码与 PyInstaller `_internal/assets`，不引用开发机绝对路径。
- 每个平台脚本都会运行真实打包后冒烟测试：启动独立程序、打开含空格/中文路径的临时 Git 仓库、读取历史、验证图标、自动退出。
- 生成 SHA256 校验文件，便于发布验证。

## Windows：实际打包

在 Windows PowerShell 中执行：

```powershell
python -m pip install -r requirements.txt
python -m pip install -r packaging/requirements-build.txt
powershell -ExecutionPolicy Bypass -File .\packaging\build-windows.ps1
```

产物：

```text
dist/GitDesk/GitDesk.exe
release/GitDesk-1.0.0-windows-x64.zip
release/GitDesk-1.0.0-windows-x64.zip.sha256
```

将 ZIP 解压到任意位置，双击 `GitDesk.exe` 即可。也可在便携目录内继续使用现有 `install-windows.ps1` 创建图标快捷方式。

### Windows 签名（可选）

没有代码签名证书时，Windows SmartScreen 可能提示未知发布者，这是正常的未签名提示，**不应要求用户绕过安全策略**。正式分发可使用：

```powershell
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 `
  /f your-certificate.pfx /p your-password .\dist\GitDesk\GitDesk.exe
```

请安全保管证书，不把密码或 PFX 提交到仓库。

## Linux：AppDir / 压缩包

```sh
python3 -m pip install -r requirements.txt packaging/requirements-build.txt
sh packaging/build-linux.sh
```

产物：

```text
dist/GitDesk.AppDir/AppRun
release/GitDesk-1.0.0-linux-x64.tar.gz
```

直接运行：

```sh
./dist/GitDesk.AppDir/AppRun /path/to/repo
```

系统需要桌面运行库，例如 Debian/Ubuntu：

```sh
sudo apt install libxcb-cursor0 libgl1 libegl1 libxkbcommon-x11-0
```

如需 `.desktop` 菜单图标，可运行项目里的 `install-linux.sh`，或在 AppDir 中安装对应 desktop 文件。

### AppImage（可选）

当前流程生成 **AppDir**，不强行下载第三方工具。需要单文件 AppImage 时，在可信来源下载 `appimagetool` 后：

```sh
appimagetool dist/GitDesk.AppDir release/GitDesk-x86_64.AppImage
chmod +x release/GitDesk-x86_64.AppImage
```

AppImage 运行仍需目标系统基础桌面库和 FUSE；没有 FUSE 时可使用 `--appimage-extract-and-run`。

## macOS：.app / DMG

```sh
python3 -m pip install -r requirements.txt packaging/requirements-build.txt
sh packaging/build-macos.sh
```

产物：

```text
dist/GitDesk.app
release/GitDesk-1.0.0-macos.dmg
```

本地测试：

```sh
open dist/GitDesk.app
```

未配置签名时生成的是**本地开发包**，不是已完成 Apple 公证的正式分发包。其他 Mac 首次打开可能受到 Gatekeeper 限制，应使用正式 Developer ID 签名和公证，不建议绕过安全检查。

### 签名与公证（可选）

配置环境变量后运行构建脚本：

```sh
export APPLE_ID="developer@example.com"
export APPLE_TEAM_ID="YOURTEAMID"
export APPLE_APP_PASSWORD="app-specific-password"
sh packaging/build-macos.sh
```

`codesign` 对本地开发包默认使用 ad-hoc 签名（`GITDESK_SIGN=0` 可禁用）。正式分发前请替换为你的 Developer ID Application 证书，并检查 `Info.plist` 的 bundle ID、版本号和权限。

## CI 自动构建

[.github/workflows/build.yml](../.github/workflows/build.yml) 提供：

- `windows-latest`、`ubuntu-latest`、`macos-latest` 三个构建任务。
- Python 3.12、依赖缓存、全部单元测试。
- 每个平台独立构建 + 冒烟测试。
- `release/*` 作为构建产物上传。
- 支持手动运行（`workflow_dispatch`）和 `v*` 标签触发。

CI 的 macOS 默认构建**未签名开发包**，不会自动使用私有证书。正式发布时通过受保护的 CI Secrets 配置签名，证书和密码不要写入 workflow 文件。

### 安装程序优先的自动发布

`Build GitDesk` 工作流现在统一执行：

1. Windows 生成 **Setup.exe**，执行真实安装、启动和卸载验证。
2. Linux 生成 **AppImage**，macOS 生成标准 **.app + DMG**。
3. 各平台上传 Actions Artifact。
4. 推送 `v*` 标签时，自动创建或更新同名 GitHub Release 并上传安装程序，**不需要手工下载后再上传**。

ZIP/tar.gz 仅用于本地便携测试或备用分发，**不上传 Actions Artifact，也不进入正式 Release**。正式附件只有安装程序与 SHA256 校验文件。发布权限使用仓库 `GITHUB_TOKEN`，无需额外个人令牌。

## 发布前检查清单

- [ ] `python -m unittest discover -s tests -v` 全部通过。
- [ ] 打包后冒烟测试通过（脚本已自动执行）。
- [ ] 在**没有 Python 环境**的目标系统上验证启动、图标、仓库打开、提交和推送。
- [ ] 检查中文路径、空格路径、分支历史图和高 DPI 显示。
- [ ] 验证压缩包 SHA256。
- [ ] Windows 签名、macOS Developer ID 签名与公证（若公开分发）。
- [ ] 明确 Qt/PySide6 等第三方许可证及本机 Git 不作为应用捆绑分发。

## 常见问题

**Q：能生成一个单独的 `.exe` 吗？**  
A：可以改 PyInstaller 为 onefile，但本项目默认 onedir：启动更快、没有每次解压 Qt 的开销，排错也更简单。单文件仍需将 Git 安装在用户机器上。

**Q：打包后是否无需安装 Git？**  
A：不是。GitDesk 调用用户本机 Git，继承其 SSH、凭据和配置。打包只包含 Python/Qt/应用代码，不包含 Git 可执行文件。

**Q：为什么 Linux/macOS 不能直接在 Windows 构建？**  
A：PyInstaller 会收集当前系统的原生可执行文件与 Qt 动态库，不能交叉生成本地应用。请使用对应系统或 CI 构建。
