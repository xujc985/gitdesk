> 当前版本使用 **PySide6 Qt Widgets 原生界面**，不再使用 tkinter。首次运行请执行 `python -m pip install -r requirements.txt`，或直接运行 `run.bat` 自动安装依赖。

本指南按日常工作流组织，覆盖 GitDesk 的全部功能。

## 1. 启动与打开仓库

启动后进入**欢迎页**，提供四个入口：

- **打开本地仓库…**：选择一个已存在的 Git 仓库目录。
- **克隆远程仓库…**：填写仓库地址与目标目录，克隆过程实时显示进度。
- **初始化新仓库…**：把一个普通目录变成 Git 仓库（`git init`）。
- **最近打开**：一键回到最近用过的仓库（最多记忆 8 个）。

打开后，标题栏显示仓库名与路径，工具栏右侧显示**当前分支**与**同步状态**。

## 2. 变更、暂存与差异

切换到「**变更**」标签页，文件按四组展示：

- **冲突**：合并/变基产生冲突的文件（红色）。
- **已暂存**：已 `git add`，将随下次提交入库。
- **未暂存的更改**：已跟踪文件被修改但未暂存。
- **未跟踪**：新文件。

**右键任意文件**：

| 操作 | 说明 |
|------|------|
| 暂存 (Add) | `git add` |
| 取消暂存 | `git restore --staged` |
| 回滚更改 (Rollback) | 丢弃工作区修改（**不可恢复**，会二次确认） |
| 删除文件 | 删除未跟踪文件（二次确认） |
| 查看差异 | 在右侧差异预览区显示该文件的 diff |

点击文件即在右侧看到**语法着色的差异预览**：绿色为新增、红色为删除、蓝色为 hunk 头。勾选「并排」可打开左右同步滚动的对比窗口。

- **逐块暂存**：右键普通修改文件 →「逐块暂存…」，勾选需要的 `@@` 差异块，只有选中的代码进入暂存区，工作区不变。
- **冲突处理**：冲突文件右键可查看我方/对方原文，选择「保留我方」或「保留对方」并标记解决。复杂冲突仍可手动编辑，然后暂存。

## 3. 提交

「变更」页顶部是提交区：

1. 在**提交信息**框填写说明（支持多行）。
2. 勾选 **修改上一次提交 (Amend)** 可修补最近一次提交。
3. 点 **提交** 或按 **Ctrl+Enter**。

> 若没有已暂存的更改，GitDesk 会询问是否**暂存全部更改并提交**（PyCharm 的默认行为）。

## 4. 历史

「**历史**」标签页展示 PyCharm 风格的**彩色分支提交图**：

- 蓝、绿、黄、紫等彩色轨道表示不同分支；圆点表示提交，平滑连线表示真实父子关系。
- 分叉处向新轨道展开，合并提交用多条连线连接各父提交；HEAD 用双圈节点标记。
- 历史默认加载最近 200 个提交；点击「加载更早」可每次追加 200 个，控制大仓库前端资源占用。
- 点击圆点或提交行查看详情；上下滚动时图形与提交列表同步。

- **过滤条**：按分支、按提交信息关键词筛选，回车或点「应用」生效。
- **提交图**：左侧 `*` / 连线显示分支拓扑；提交信息后跟 `⟨HEAD -> master, tag: v1.0⟩` 引用标签；当前 HEAD 提交以绿色高亮。
- **提交详情**：选中提交后，右侧显示完整信息（哈希、作者、日期、统计）与**本次提交的文件列表**，**双击文件**弹出该文件的 diff 窗口。

**右键某条提交**：

| 操作 | 说明 |
|------|------|
| 在此提交上新建分支… | 以该提交为起点建分支并切换 |
| 检出 | 进入 detached HEAD 查看历史状态 |
| 为此提交打标签… | 在该提交上创建标签 |
| 摘樱桃 (Cherry-pick) | 把该提交应用到当前分支 |
| 还原此提交 (Revert) | 生成一个反向提交撤销它 |
| 重置当前分支到此提交… | soft / mixed / hard 三种模式 |
| 复制提交哈希 | 复制完整 SHA |

## 5. 分支

「**分支**」标签页分两棵树：**本地分支**（当前分支带 `✓` 且绿色）与**远程分支**（紫色）。

- **双击**分支：检出（远程分支会自动建本地跟踪分支）。
- **右键分支**：检出、新建分支（以此为起点）、重命名、合并到当前分支、变基当前分支到此分支、删除（本地未合并会提示强删；远程分支删除会操作远程仓库）。
- 追踪列显示上游分支与 **↥领先 / ↧落后** 数量。

新建分支也可通过工具栏「**新建分支**」按钮，可指定起点并选择是否立即切换。

## 6. 远程同步

通过工具栏或「仓库」菜单：

- **获取 (Fetch)**：`git fetch --all --prune`，只同步不动工作区。
- **拉取 (Pull)**：可勾选**使用变基 (rebase)**。
- **推送 (Push)**：可选远程、设置上游（-u）、同时推送标签、**强制推送（--force-with-lease，安全的强推）**。
- **远程仓库管理…**：查看 / 添加 / 删除 / 修改远程地址。

推送前建议先「获取」查看是否落后；状态栏与分支指示器会实时反映同步状态。

## 7. Stash（贮藏）

- **贮藏更改…**：可填写说明、勾选**包含未跟踪文件**、**保留已暂存内容**。
- 「**Stash**」标签页列出全部贮藏，选中即在右侧预览 diff。
- **右键贮藏**：**应用 (Apply)**（保留贮藏）、**弹出 (Pop)**（应用并删除）、**删除 (Drop)**（二次确认）。

## 8. 标签

「**标签**」标签页列出全部标签（含类型：附注 / 轻量）。

- **新建标签…**：填写标签名、可选目标提交（留空 = HEAD）、可选说明（留空 = 轻量标签）。
- **右键标签**：检出、**推送到远程**、**删除**（可勾选同时删除远程标签）。

## 9. 常见历史与合并操作

| 场景 | 入口 |
|------|------|
| 合并分支 | 「分支」菜单 → 合并到当前分支…（可选 --no-ff / --squash） |
| 变基 | 「分支」菜单 → 变基当前分支… |
| 解决冲突 | 冲突文件红色列于「变更」页 → 手动编辑解决 → 暂存 → 提交 |
| 中止合并 / 变基 | 「仓库」菜单 → 合并冲突中止 / 变基中止 |
| 继续变基 | 解决冲突并暂存后 → 「仓库」菜单 → 继续变基 |
| Cherry-pick | 历史页右键提交 → 摘樱桃 |
| Revert | 历史页右键提交 → 还原此提交 |
| Reset | 历史页右键提交 → 重置当前分支到此提交（soft/mixed/hard） |

发生合并冲突时，顶部会出现 **⚠ 合并进行中** 提示；解决完所有冲突文件并暂存后，正常提交即完成合并。

## 10. 快捷键

| 快捷键 | 作用 |
|--------|------|
| `F5` | 刷新全部视图 |
| `Ctrl+O` | 打开仓库 |
| `Ctrl+Shift+N` | 新建分支 |
| `Ctrl+K` | 跳到「变更」页提交信息框 |
| `Ctrl+Enter` | （提交信息框内）提交 |
| `Esc` | 关闭对话框 |

## 11. 常见问题

**Q：推送 / 拉取要求登录怎么办？**
A：GitDesk 直接调用本机 git，凭据由 git 自己的凭据管理器处理（Windows 凭据管理器 / SSH agent / credential helper）。首次在命令行登录过的仓库，GitDesk 里同样可用。

**Q：为什么启动后看不到提交图？**
A：仓库可能还没有任何提交。先在「变更」页做一次提交。历史默认加载 200 条，可点击「加载更早」继续查看。

**Q：前端是什么技术？内存会不会很大？**
A：使用原生 Qt Widgets，不是 Electron，也没有 WebView/浏览器进程。实测 200 提交仓库约 117 MB（包含 Python 和 Qt 运行库，机器不同会有差异）。

**Q：强制推送安全吗？**
A：GitDesk 使用 `--force-with-lease` 而非 `--force`：只有当远程分支仍在你上次获取的位置时才允许覆盖，避免覆盖他人新提交。

**Q：支持子模块 / Worktree 吗？**
A：后端已封装 `submodule status/update/add` 与 `worktree list/add/remove`，当前版本未在 UI 暴露，可通过「仓库」菜单的扩展入口或后续版本加入。

**Q：如何彻底卸载？**
A：删除本目录即可。用户设置保存在 `~/.gitdesk/settings.json`（仅最近打开列表与窗口位置），可一并删除。
