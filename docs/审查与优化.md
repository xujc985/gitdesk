# GitDesk 项目审查与优化记录

## 本轮目标

以真实使用体感为中心审查项目，重点改进历史可视化、布局、响应性与 Git 操作安全。

## 已落实

### 历史图与界面

- 使用 `git log --topo-order` 和真实父哈希 `%P` 构建拓扑；不再仅显示 `--graph` 的 `*` 字符。
- 新增 `graph_layout.py`：为分叉、合并分配稳定彩色轨道；新增 `graph_widget.py`：Canvas 绘制节点及平滑分叉/合流曲线。
- 历史列表扩展至完整窗口宽度，提交、作者、日期可读性更好；下方独立显示提交详情和文件差异。
- 各标签页独立布局，移除多个视图共享右侧窗格造成的空白区域。

### 体感

- 提交图和文件列表统一 24px 行高，鼠标滚轮与滚动条同步。
- 获得焦点自动同步外部改动（2 秒节流），定时刷新仅更新当前视图。
- 写操作与后台读取分别提示；避免普通状态读取打扰用户。
- 未跟踪文件可以直接预览内容；文件同时有暂存和未暂存修改时显示相对 HEAD 的完整差异。
- 保存并恢复窗口大小与位置；重复选择不再被旧请求覆盖。

### 正确性与安全

- 所有 Git 写操作串行执行；普通读取仍可后台并发。
- 后台确认框移至主线程，不在 Git 工作线程创建 Tk 组件。
- 回调增加仓库身份、选择代际校验，避免旧任务覆盖新界面。
- 仓库子目录自动定位到根目录，保证提交文件路径解析一致。
- `status -z` + 游标解析支持中文、空格、重命名路径。
- 冲突文件仅在“冲突”组展示，避免三组重复。
- 空仓库已暂存文件的回滚不再静默失败。
- Stash 预览/apply 使用不可变 SHA；drop 前核对 SHA。
- 分离 HEAD 推送显式使用 `HEAD:refs/heads/<目标分支>`。
- 新增“继续变基”菜单入口。

## 测试

视觉验证使用真实多分支、二次合并仓库生成 `screenshot-rainbow-log.png`。
