# Qt 前端优化说明

## 技术选择

GitDesk 已完全从 tkinter 迁移到 **PySide6 Qt Widgets**。不采用 Electron、Tauri/WebView 或浏览器内嵌页面：本应用的主要工作是表格、分支图和文本差异，Qt 原生控件能提供足够的视觉质量，架构更简单。

依赖仅为 `PySide6-Essentials`，不包含 QtWebEngine。启动入口为 `main.py` / `gitdesk.pyw`。

## 视觉提升

- 以深色编辑器背景、次级面板、三级悬浮按钮构成层次，不再所有区域同一种灰色。
- 统一字体、行高、内边距、圆角、滚动条、选中色与输入框焦点。
- 分支/标签使用独立徽标，避免整行提交引用难以阅读。
- 历史轨道使用 QPainter 抗锯齿曲线，支持真实拓扑分叉与合并。
- Qt Fusion 原生绘制支持 Windows 高 DPI，无图片主题资源。

## 轻量策略与实测

### 不无限创建后台线程

`ui_qt/tasks.py` 中只有一个 `QThread`。任务按队列执行，重复读取更新为最新回调，旧仓库结果不派发。所有 GUI 回调由 Qt 信号在主线程执行。

### 长历史有界

- 默认读取最近 200 个提交，工具栏“加载更早”每次增加 200 个。
- 表格使用 `QAbstractTableModel`，不为每个单元格创建独立 QWidget。
- 分支图用 `QGraphicsScene` 只保留当前可见提交与连接，滚动时重建可见部分。
- 性能检查：200 个提交约 38 个可见绘图对象，而不是全量历史对象。

### 文本资源上限

- 差异预览最大约 1.2 MB；更大的内容显示截断提示。
- `QPlainTextEdit` 使用轻量纯文本文档，最大 50,000 块。
- 差异高亮按文本块规则处理，不使用每行 HTML 或大量富文本控件。

### 内存基线

Windows 11 / Python 3.14 / PySide6 6.12 实测工作集参考：

| 场景 | 工作集 |
|------|-------:|
| 欢迎页 | 约 110 MB |
| 打开含 200 个提交的仓库 | 约 117 MB |

该数值包含 Python 解释器、Qt 运行库和全部已加载视图。比 tkinter 基础开销高，但远低于通常包含独立浏览器内核的桌面封装。后续可通过按需创建非活动页面进一步降低，但需平衡切换延迟。

## 验证

- 57 项 unittest：后端 Git、Unicode 路径、彩色拓扑、Qt 真实窗口/后台线程/提交/合并、长历史与差异限量、旧配置兼容、仓库切换、提交失败草稿保留与关闭队列排空。
- Qt 测试默认 `QT_QPA_PLATFORM=offscreen`，无需用户点击。
- `docs/screenshot-qt.png` 是真实多分支仓库窗口渲染，不是设计稿。

## 后续可选优化

- 非活动页面延迟创建（减少基础内存，但首次切页略有延迟）。
- 大仓库图按需分页、分支隐藏与拓扑裁剪。
- 差异分页、并排 diff、冲突三方编辑。
- Qt `QSvgRenderer` 小图标替代文字符号；不引入大型图标包。
