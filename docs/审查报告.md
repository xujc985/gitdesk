# GitDesk 代码审查报告（Qt 版）

## 结论

本轮审查覆盖启动脚本、Qt 任务调度、仓库切换、后台退出、变更提交、历史/分支/Stash/标签页面，以及 Git 后端路径处理。

发现的高优先级问题已修复，并补充回归测试。**当前 57 项测试全部通过；Windows 双击 `run.bat` 已实际启动并确认窗口正常响应。**

## 已修复问题

### P0：后台任务执行与退出

- **问题**：任务执行信号的发出线程可能影响 Qt 槽函数执行位置，不能保证 Git 在 worker 中执行；忙碌退出还可能因队列未排空而永久等待。
- **修复**：显式 worker 调度器 + `QueuedConnection` 任务信号；主线程只负责提交任务和处理结果。关闭后不再接收新任务，但已接受任务继续排空，最后一项完成后退出线程。
- **测试**：验证执行函数在 worker、结果在 GUI 线程；忙碌时关闭能按顺序完成队列并退出。

### P1：新仓库读取被误判为旧任务

- **问题**：切换仓库时页面尚未初始化，读取任务被按旧上下文跳过，导致历史、分支和变更列表为空。
- **修复**：新仓库先设置页面上下文，再启动读取；页面回调额外验证 repo 身份和请求代际，旧页面不会覆盖新内容。
- **测试**：连续打开不同仓库，验证历史与当前分支正确回填。

### P1：重复刷新与关闭边界

- **问题**：打开仓库重复连接标签页信号，切页次数越多刷新越多；旧窗口配置可能直接阻止启动。
- **修复**：标签页信号只连接一次；非法旧 tkinter 配置安全忽略，Qt 配置以十六进制保存。
- **测试**：旧格式 `1280x800+0+0` 不再导致启动失败。

### P1：提交草稿与重复提交

- **问题**：提交中可重复点击，成功或失败反馈可能受旧仓库状态影响。
- **修复**：提交中禁用按钮；仅当前仓库成功提交才清空草稿；失败恢复按钮、保留文本并显示错误；写操作结果不因切换仓库而静默丢弃。
- **测试**：真实 Git 身份错误下保留提交说明并恢复按钮。

### P2：功能与体验一致性

- 历史刷新保留当前选中的提交。
- 标签推送可选择远程，删除标签有确认提示。
- 写操作失败统一显示错误并刷新状态，不让 UI 与 Git 实际状态脱节。
- 非仓库欢迎页避免多余 Git 子进程；仓库子目录仍可定位根目录。

## 当前仍需注意

- `QThread.wait()` 有等待上限；极端慢速网络操作仍需后续增加“后台完成再退出”的非阻塞提示流程，避免用户等待过久。
- 目前尚未实现逐块暂存、并排 diff、三方冲突编辑和交互式 rebase。
- 大历史采用每批 200 条的“加载更早”，不是无限流式加载。
- Qt 基础内存高于 tkinter；优势是原生高 DPI、控件和抗锯齿绘图，而非最小内存。

## 后续优先级

1. 非阻塞退出等待与网络操作可取消/超时反馈。
2. 冲突三方编辑与 ours/theirs 选择。
3. 逐块暂存、并排 diff、大仓库历史分页。
4. 非活动页面延迟创建以进一步降低启动内存。
